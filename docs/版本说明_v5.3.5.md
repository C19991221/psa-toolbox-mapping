## 这个版本多了什么

v5.3.5 是两个**车机侧注入补丁** + 一处**下载交互**。界面结构、按键映射载荷都与 v5.3.4 相同，装这一版**不需要重新点「注入」**（注入载荷的键码没变）；但要用下面两个新开关，得先点一次「维护诊断 → 修复PSA工具箱」把新补丁注进去。

### 一、导航助手：保持仪表投屏，不被高德空报文清掉

装第三方 CarPlay 客户端（DiPlay）后，仪表投屏会**一闪一闪地回到原厂罗盘**。

原因是车机自带高德**每秒都在发导航报文**，没导航时里面的路名是空的，公共服务（`com.cusc.misc`）把这种空报文当成「清除导航」，每次都往 `IP_NAV_INFO` 写一帧「没有导航」；DiPlay 那边每秒又把导航画面写回来。两边对着写，仪表就闪。

这版在注入层拦掉**空报文那一帧**：

- 开关打开 ⇒ 空报文什么都不发，投屏由 DiPlay 独占；真实导航报文照旧下发，退出导航时的清屏也不受影响。
- 开关关掉 ⇒ 完全等于原厂行为（逐字节等价）。
- 属性 `persist.psa.navi.keep`，界面在「导航助手」页。

⚠ 这个开关只解决「闪回罗盘」。如果 DiPlay 自己不发画面，仪表当然还是空的。

### 二、音乐助手：导航播报时，旋钮调的是导航音量

408 的中控音量旋钮**不产生 KeyEvent**，公共服务是按「当前谁占着音频焦点」决定拧旋钮调哪组音量的。CarPlay 播报时用的是 ducking，焦点一直留在客户端手里 ⇒ 播报期间拧旋钮调的是**媒体**音量，越拧越吵，导航播报本身没变响。

这版的补丁在焦点包名读出来之后加一层判断：

- 焦点是 `com.shihab.diplay`、且 `Settings.Global` 的 `diplay_nav_prompt == 1` ⇒ 当作 `com.autonavi.amapauto`，拧旋钮调**导航**音量。
- 其它情况原样返回，一行都不改；`appContext` 为空时也原样返回。
- 属性 `persist.psa.volume.nav`，界面在「音乐助手」页。

⚠ **必须有 DiPlay 客户端定期写 `diplay_nav_prompt`**（它自己播报时置 1、播完置 0）。不写这个值，开关打开也不会变。

### 三、两个开关都会灰显

两个开关的可用性不是写死的，而是每次进页面时**扫一遍已装的 `com.cusc.misc`**，看里面有没有这一版补丁的方法名：

- 没注入 / 注入失败 / 装的是原厂包 ⇒ 开关灰显，下方提示「公共服务还没有注入这一条补丁，请先点『维护诊断 → 修复PSA工具箱』」。
- 注入了 ⇒ 可以正常开关。

这样不会出现「开关能点、其实什么都没做」。

### 四、检查更新：可以取消，也可以后台下

原来的下载只有一条进度条，退出弹窗就中断。现在：

- 下载按钮自己变成进度条（左半铺色、文字跟着进度变色）。
- 弹窗可以**最小化到后台**继续下，关于页会显示「正在下载，点这里查看」。
- 可以**取消**：先等下载协程真正退出，再删半截文件，不会留下坏包。

## 升级方式

1. 车机装本包（覆盖安装，`versionCode` 12，签名与上一版一致）。
2. 打开「维护诊断 → 修复PSA工具箱」，等注入完成（这一步会把两个新补丁写进公共服务）。
3. 进「导航助手」/「音乐助手」，确认两个新开关不是灰的。
4. DiPlay 侧需要写 `diplay_nav_prompt`，第二个开关才会有效果。

## 已知限制

- **两个补丁都还没在车上跑过完整验收**。离线侧做了 16 版固件 × debug true/false 的补丁回归（32/32 通过，真打补丁、真打包、校验 dex 不变量），锚点在 408 基线上各唯一命中一次；这只证明能打出合法的 dex，**不证明运行时行为**。
- 补丁的落点是按固件文本匹配的，一共 5（导航）+ 3（音量）个锚点变体。遇到没见过的固件，锚点一条都命中时**不会报错、也不会生效**，此时界面会灰显，不会假装成功。
- 第二个开关依赖 DiPlay 客户端写那个 Settings 值，我们这边无法替他保证时序；如果他写得太晚或忘了清零，旋钮可能短暂调错音量组。
- 导航那条只丢空报文，**不接管** DiPlay 的投屏；DiPlay 自己不刷新时仪表依然不动。
